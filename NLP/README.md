# 자연어 처리 입문: RNN에서 Transformer, BERT와 GPT까지

컴퓨터가 문장을 읽고 다음 단어를 예측하거나 번역문을 만드는 과정을 배웁니다. 먼저 텍스트를 숫자로 바꾸는 방법과 학습의 의미를 이해한 뒤, 각 모델이 앞 단계의 어떤 어려움을 해결하는지 살펴봅니다.

수식은 계산을 확인하고 싶을 때 읽으면 됩니다. 설명과 예시는 수식 없이도 따라갈 수 있도록 구성했습니다. 코드 모양의 계산식은 실행용 코드가 아닌 설명용 표기이며, 예시의 숫자는 실제 모델에서 측정한 값이 아닙니다.

## 학습 순서

| 순서 | 이번 단계의 질문 |
| --- | --- |
| 1. 토큰과 임베딩 | 문장을 어떻게 숫자로 바꿀까? |
| 2. 예측과 학습 | 모델은 무엇을 맞히고 무엇을 수정할까? |
| 3. RNN | 앞에서 읽은 내용을 다음 계산에 어떻게 전달할까? |
| 4. LSTM | 필요한 정보를 더 오래 유지하려면? |
| 5. Seq2Seq | 입력 문장을 읽고 다른 문장을 만들려면? |
| 6. Attention | 입력의 마지막 요약만으로 부족하다면? |
| 7. Transformer | 이전 순환 상태를 기다리지 않고 문맥을 계산하려면? |
| 8. BERT와 GPT | 입력 안의 토큰 복원과 다음 토큰 예측은 어떻게 다를까? |

이 순서는 개념을 연결하기 위한 순서입니다. 모든 이름이 같은 종류의 모델을 뜻하거나, 뒤의 기술이 앞의 기술을 완전히 대체했다는 의미는 아닙니다.

## 1. 문장을 숫자로 바꾸기

### 1-1. 토큰: 텍스트를 처리하는 단위

**자연어 처리(NLP, Natural Language Processing)**는 사람이 사용하는 언어를 컴퓨터로 분석하거나 생성하는 분야입니다. 번역, 문장 분류, 질문에 답하기 등이 여기에 포함됩니다.

이 노트에서는 문장을 읽고 토큰을 예측하는 **신경망**을 다룹니다. 신경망은 가중치가 있는 계산들을 연결하고, 학습으로 그 가중치를 조정하는 모델입니다. 숫자로 계산하므로 텍스트를 먼저 숫자로 바꿔야 합니다.

**토크나이저(tokenizer)**는 텍스트를 처리 단위인 **토큰(token)**으로 나누고, 각 토큰에 대응하는 ID를 찾습니다.

```text
문장:       나는 이 영화를 좋아한다
토큰:       [나는] [이] [영화를] [좋아한다]
토큰 ID:    [12]   [35] [208]   [91]
```

여기서는 이해하기 쉽도록 띄어쓰기 단위를 토큰으로 가정합니다. 실제 토크나이저는 단어를 더 작은 조각으로 나눌 수도 있습니다. 위 ID는 설명용이며, 숫자가 크다고 더 중요한 토큰이라는 뜻은 아닙니다.

### 1-2. 임베딩: ID를 숫자 벡터로 바꾸기

토큰 ID는 항목을 구분하는 번호입니다. 모델에는 그 번호에 대응하는 **임베딩(embedding)**을 입력합니다. 임베딩은 여러 숫자를 순서대로 모은 **벡터(vector)**입니다.

```text
토큰 '영화를'
    → ID 208
    → 임베딩 표의 208번 항목 조회
    → [0.2, -0.7, 0.5, 0.1]
```

이 예시는 숫자 4개를 쓰므로 4차원 벡터입니다. 실제 모델의 차원 수는 설계에 따라 달라집니다. 임베딩 표 전체를 **임베딩 행렬**이라고 하며, 보통 이 표의 값도 모델 학습 중에 바뀝니다.

각 숫자에 사람이 ‘긍정’, ‘영화’, ‘과거형’ 같은 뜻을 하나씩 정해 주지는 않습니다. 모델은 여러 성분의 조합을 이용해 예측에 필요한 정보를 표현합니다.

이 조회 단계에서는 같은 토큰 ID에 같은 벡터가 대응합니다. 이후 RNN이나 Transformer가 문장의 다른 토큰 정보를 반영하면, 같은 토큰도 문맥에 따라 다른 내부 표현을 갖게 됩니다. **입구의 임베딩과 문맥을 반영한 상태는 구분해야 합니다.**

## 2. 예측과 학습은 무엇인가?

### 2-1. 다음 토큰을 예측하는 예시

다음 입력 뒤에 올 토큰을 예측한다고 하겠습니다.

```text
입력: 나는 이 영화를
다음 정답 토큰: 좋아한다
```

모델은 토크나이저에 등록된 후보 토큰 전체에 대해 점수를 계산합니다. 이 후보 목록을 **어휘 집합(vocabulary)**, 확률로 바꾸기 전 점수를 **로짓(logits)**이라고 합니다.

**Softmax**는 후보별 점수를 합이 1인 확률분포로 바꾸는 함수입니다. 아래는 세 후보를 따로 표시하고 나머지 후보의 확률을 합쳐 표시한 예시입니다.

| 후보 토큰 | 모델이 부여한 확률 |
| --- | ---: |
| 좋아한다 | 0.60 |
| 싫어한다 | 0.25 |
| 봤다 | 0.10 |
| 나머지 모든 후보의 확률 합 | 0.05 |

가장 확률이 높은 토큰을 고르면 `좋아한다`가 선택됩니다. 확률에 따라 무작위로 뽑는 방식도 있으며, 같은 확률분포라도 선택 방식에 따라 결과는 달라질 수 있습니다.

### 2-2. 손실: 정답을 얼마나 잘 예측했는가

학습할 때는 데이터에 있는 다음 토큰을 정답으로 사용합니다. 위 문장에서 정답이 `좋아한다`라면, 그 토큰에 높은 확률을 줄수록 작아지는 **손실(loss)**을 계산합니다. 실제 문장은 다른 토큰으로도 자연스럽게 이어질 수 있지만, 이 학습 예시에서는 데이터에 기록된 토큰을 정답으로 삼습니다.

```text
한 토큰의 손실 = -log(정답 토큰에 부여한 확률)

정답 확률 0.10 → 손실 약 2.303
정답 확률 0.60 → 손실 약 0.511
정답 확률 0.90 → 손실 약 0.105
```

여기서 log는 자연로그입니다. 문장 학습에서는 여러 위치의 손실을 더하거나 평균 내서 사용합니다. 각 위치에서 어휘 후보 하나를 정답으로 삼을 때, 위 손실은 **교차 엔트로피(cross-entropy)**에 해당합니다. 토큰을 실제로 뽑아 정답인지 확인한 뒤 학습하는 것이 아니라, 정답에 부여한 확률로 손실을 계산합니다.

### 2-3. 무엇이 바뀌는가: 파라미터와 계산 결과

**파라미터(parameter)**는 학습으로 조정하는 모델의 숫자입니다. 대표적으로 입력 성분을 조합하는 **가중치(weight)**와, 그 가중합에 더하는 **편향(bias)**이 있습니다.

**역전파(backpropagation)**는 각 파라미터를 조금 바꾸면 손실이 어느 방향으로 얼마나 달라지는지 나타내는 **기울기(gradient)**를 계산합니다. **옵티마이저(optimizer)**는 이 기울기를 이용해 손실을 줄이는 방향으로 파라미터를 수정합니다.

```text
입력으로 예측 계산
    → 정답에 대한 손실 계산
    → 역전파로 파라미터별 기울기 계산
    → 옵티마이저로 파라미터 갱신
    → 다른 학습 예시에서도 반복
```

반면 **추론(inference)**은 학습한 모델로 새로운 입력의 예측을 구하는 과정입니다. 일반적인 추론에서는 파라미터를 고정합니다. 입력이 달라져 예측 결과가 바뀌는 것은 재학습이 아닙니다.

앞으로도 **‘학습해서 저장하는 가중치’와 ‘그 가중치로 이번 입력에서 계산한 값’**을 구분해야 합니다.

## 3. RNN: 앞에서 읽은 내용을 상태로 전달하기

### 3-1. 왜 이전 상태가 필요한가?

토큰 임베딩만 하나씩 보면 앞에서 어떤 문장을 읽었는지 알 수 없습니다. 예를 들어 `영화를` 다음에 올 토큰을 예측하려면, 그 앞에서 읽은 내용도 이용할 수 있어야 합니다.

**RNN(Recurrent Neural Network, 순환 신경망)**은 현재 입력과 이전 상태를 함께 사용해 새 상태를 계산합니다. 전달되는 벡터를 **hidden state(은닉 상태)**라고 합니다.

```text
처음 상태
    ↓ '나는' 입력
첫 상태: '나는'까지 읽은 정보를 표현
    ↓ '이' 입력
둘째 상태: '나는 이'까지 읽은 정보를 표현
    ↓ '영화를' 입력
셋째 상태: '나는 이 영화를'까지 읽은 정보를 표현
```

상태는 원문을 그대로 저장한 문장이 아닙니다. 앞의 정보를 예측에 활용할 수 있도록 계산한 고정 크기의 숫자 벡터입니다.

### 3-2. 한 시점의 계산

한 시점의 입력과 이전 상태로 새 상태를 만드는 계산 단위를 **셀(cell)**이라고 합니다. 기본 RNN 셀은 다음처럼 계산합니다.

```text
새 상태 = tanh(입력 가중치 × 현재 입력
             + 순환 가중치 × 이전 상태
             + 편향)
```

여기서 `×`는 행렬과 벡터의 곱입니다. `tanh`는 각 성분을 −1과 1 사이로 바꾸는 비선형 함수입니다. 비선형 함수를 사용하면 가중합만 반복할 때보다 복잡한 입력 관계를 표현할 수 있습니다. 첫 상태는 보통 0 벡터로 시작합니다.

셀을 여러 층으로 쌓을 수도 있습니다. 이때 아래 층의 상태가 위 층의 입력이 됩니다. 여기서는 시간에 따른 흐름에 집중하기 위해 한 층을 기준으로 설명합니다.

**같은 층에서는 모든 시점에 같은 셀과 가중치를 사용합니다.** ‘나는’를 처리하는 셀과 ‘영화를’를 처리하는 셀을 따로 학습하는 것이 아닙니다. 시점마다 입력과 상태가 달라집니다.

새 상태에 **어휘 출력층**을 연결하면 다음 토큰을 예측할 수 있습니다.

```text
'나는 이 영화를'까지 읽은 hidden state
    → 어휘 출력층: 후보 토큰별 점수 계산
    → softmax: 후보 토큰별 확률 계산
    → 다음 토큰 선택
```

RNN 셀은 상태를 갱신하고, 어휘 출력층은 그 상태를 토큰별 점수로 바꿉니다. 두 부품의 역할은 다릅니다.

### 3-3. 남은 어려움: 오래된 정보 유지

RNN은 새 토큰을 읽을 때마다 이전 상태를 다시 변환합니다. 이 과정이 길어지면 앞부분의 정보가 약해질 수 있습니다.

학습에서도 문제가 생길 수 있습니다. 여러 시점을 거슬러 기울기를 계산할 때 그 값이 지나치게 작아지는 **기울기 소실**, 지나치게 커지는 **기울기 폭주**가 발생할 수 있습니다. 특히 기울기가 소실되면, 앞의 정보를 나중까지 유지하도록 가중치를 수정하기 어렵습니다.

다음의 LSTM은 별도 기억 통로와 게이트를 추가해 **멀리 떨어진 토큰 사이의 관계인 장기 의존성**을 학습하도록 돕습니다.

## 4. LSTM: 무엇을 유지하고 새로 기록할지 조절하기

### 4-1. 두 상태를 구분하자

**LSTM(Long Short-Term Memory)**은 RNN에 사용하는 셀의 한 종류입니다. 여기서는 세 게이트를 사용하는 표준적인 LSTM을 설명합니다.

| 상태 | 기호 | 역할 |
| --- | --- | --- |
| Cell state | c | 기존 기억을 유지하면서 새 내용을 반영하는 기억 통로 |
| Hidden state | h | 현재 cell state로부터 계산해 다음 순환 계산과 출력층에 사용하는 표현 |

**두 상태 모두 다음 시점에 전달합니다.** Cell state만 다음 시점에 가고 hidden state는 출력층에만 가는 구조가 아닙니다.

### 4-2. 세 게이트와 후보 기억

**게이트(gate)**는 정보의 반영 비율을 조절하는 계산입니다. 현재 토큰의 임베딩과 이전 hidden state를 받아 벡터를 계산합니다.

| 구성 요소 | 계산하는 내용 |
| --- | --- |
| Forget gate, f | 이전 cell state를 얼마나 유지할지 |
| Input gate, i | 새 후보 기억을 얼마나 반영할지 |
| Output gate, o | 변환된 cell state를 hidden state에 얼마나 반영할지 |
| 후보 기억, g | cell state에 새로 추가할 값 |

세 게이트는 **sigmoid** 함수를 사용해 각 성분을 0과 1 사이로 만듭니다. 후보 기억은 **tanh**를 사용해 각 성분을 −1과 1 사이로 만듭니다. 후보 기억은 네 번째 게이트가 아니라 새로 저장할 내용입니다.

```text
f = sigmoid(Wf × [이전 h, 현재 입력] + bf)
i = sigmoid(Wi × [이전 h, 현재 입력] + bi)
o = sigmoid(Wo × [이전 h, 현재 입력] + bo)
g = tanh   (Wg × [이전 h, 현재 입력] + bg)
```

대괄호는 두 벡터를 이어 붙인다는 뜻입니다. 각 식의 W와 b는 서로 다른 학습 파라미터입니다. 세 게이트를 따로 계산하므로 f, i, o의 합이 1일 필요는 없습니다.

### 4-3. 왜 ‘덧셈 갱신’인가?

계산한 값으로 두 상태를 갱신합니다.

```text
새 c = (f ⊙ 이전 c) + (i ⊙ g)
새 h = o ⊙ tanh(새 c)
```

`⊙`는 같은 위치의 성분끼리 곱한다는 뜻입니다. 새 cell state는 **유지할 이전 기억과 새로 기록할 내용을 더해서** 만듭니다. 이것이 덧셈 갱신입니다.

벡터의 한 성분만 보겠습니다.

```text
이전 c = 1.0
f = 0.9, i = 0.2, g = 0.5, o = 0.7

새 c = 0.9 × 1.0 + 0.2 × 0.5 = 0.95
새 h = 0.7 × tanh(0.95) ≈ 0.518
```

`f`가 1에 가깝고 새로 더하는 항이 작으면 이전 cell state가 거의 그대로 유지됩니다. 이 직접 전달 경로가 기울기 소실을 완화하는 데 도움이 됩니다. 모든 기울기 문제를 없애거나 정보를 무한히 기억하게 하는 것은 아닙니다.

### 4-4. 게이트의 값도 학습하는가?

**학습하는 것은 게이트 값을 만드는 W와 b입니다.** 위 예시의 `f = 0.9`를 모든 문장에 고정해서 쓰지 않습니다. 같은 학습 가중치로도 현재 입력과 이전 상태에 따라 다른 f를 계산합니다. 후보 기억 g를 만드는 Wg와 bg도 함께 학습합니다.

예를 들어 `나는 이 영화를` 다음 정답이 `좋아한다`일 때, 모델이 그 정답에 낮은 확률을 줬다면 손실이 커집니다. 이 손실이 계산된 경로를 거슬러 기울기를 구하면 어휘 출력층뿐 아니라 LSTM 게이트의 가중치도 수정할 수 있습니다.

```text
앞으로 계산: 입력 → LSTM 상태 → 어휘 출력층 → 토큰 확률 → 손실
학습:       이 계산 경로를 거슬러 각 파라미터의 기울기를 구함
```

여러 시점의 순환 계산을 거슬러 역전파하는 방법을 **BPTT(Backpropagation Through Time, 시간축 역전파)**라고 합니다. RNN과 LSTM 모두 사용합니다. 같은 가중치를 여러 시점에 사용했으므로 각 시점에서 생긴 기울기의 기여를 합쳐 공유 가중치를 갱신합니다.

게이트별로 ‘이때 0.9가 정답’이라는 별도 정답을 주는 것이 아닙니다. **여러 위치의 다음 토큰 예측이 좋아지도록 모든 부품을 함께 조정합니다.** 같은 손실을 사용해도 각 파라미터의 기울기는 서로 다릅니다.

### 4-5. Output gate와 어휘 출력층은 다르다

```text
cell state
    → tanh 적용
    → output gate 값을 원소별로 곱함
    → hidden state
    → 어휘 출력층으로 후보별 점수 계산
    → softmax로 후보별 확률 계산
```

Output gate는 hidden state를 만드는 LSTM 내부 부품입니다. 어휘 출력층은 hidden state를 후보 토큰별 점수로 바꾸는 부품입니다. 이름에 ‘출력’이 들어가지만 계산 대상과 가중치가 다릅니다.

이제 문장을 읽으며 정보를 유지하는 방법을 배웠습니다. 다음에는 이 계산을 번역에 연결합니다.

## 5. Seq2Seq: 문장을 읽는 과정과 만드는 과정 연결하기

### 5-1. 번역에는 두 역할이 필요하다

**Seq2Seq(Sequence-to-Sequence)**는 입력 시퀀스를 출력 시퀀스로 바꾸는 구성을 뜻합니다. 시퀀스는 토큰처럼 순서가 있는 항목들의 나열입니다.

```text
입력 시퀀스: I / love / this / movie
출력 시퀀스: 나는 / 이 / 영화를 / 좋아한다
```

입력과 출력의 토큰 수는 같을 필요가 없습니다. 여기서는 두 LSTM을 다음 역할로 연결합니다.

| 역할 | 하는 일 |
| --- | --- |
| Encoder | 입력 문장을 읽어 상태에 요약 |
| Decoder | 그 요약을 받아 출력 토큰을 순서대로 예측 |

Encoder와 Decoder는 역할의 이름입니다. 여기서는 둘 다 LSTM을 쓰지만, 가중치는 각각 학습합니다.

### 5-2. 정확히 무엇을 전달하는가?

Encoder가 입력 4토큰을 읽었다면 마지막 상태는 `h₄`와 `c₄`입니다. 상태 크기가 같은 Encoder와 Decoder를 연결한다고 가정하면, 두 상태를 각각 Decoder의 초기 상태로 사용할 수 있습니다.

```text
Encoder: I → love → this → movie
                             │
                             ├─ 마지막 hidden state h₄
                             │       → Decoder의 초기 hidden state
                             │
                             └─ 마지막 cell state c₄
                                     → Decoder의 초기 cell state
```

`h₄`와 `c₄`를 더하는 것이 아닙니다. **두 벡터를 한 쌍으로 넘기고 각각의 역할에 사용합니다.** 구조나 상태 크기가 다르면 전달 전에 변환하는 구성이 필요할 수 있습니다.

### 5-3. Decoder가 번역문을 만드는 순서

Decoder는 시작을 알리는 특수 토큰 `<BOS>`를 첫 입력으로 받습니다. 각 단계에서 새 상태를 계산하고, 어휘 출력층과 softmax로 확률분포를 구한 뒤 토큰 하나를 선택합니다. 아래 표의 입력 토큰도 실제 LSTM에 들어갈 때는 임베딩 벡터로 바뀝니다.

| 단계 | 입력 토큰 | 함께 사용하는 상태 | 선택한 출력 토큰의 예 |
| --- | --- | --- | --- |
| 1 | `<BOS>` | Encoder에서 받은 초기 상태 | 나는 |
| 2 | 나는 | 1단계에서 만든 상태 | 이 |
| 3 | 이 | 2단계에서 만든 상태 | 영화를 |
| 4 | 영화를 | 3단계에서 만든 상태 | 좋아한다 |
| 5 | 좋아한다 | 4단계에서 만든 상태 | `<EOS>` |

`<EOS>`는 문장 종료를 나타내는 특수 토큰입니다. Decoder는 같은 LSTM과 출력층을 반복 사용하며, 입력 문장의 길이와 별개로 출력을 이어 갑니다. 학습에서는 마지막 단어 다음의 `<EOS>`도 예측 정답에 포함합니다.

### 5-4. 학습에서는 이전 정답을 입력한다

생성할 때는 직전에 모델이 고른 토큰을 다음 입력으로 사용합니다. 학습할 때는 보통 **이전 정답 토큰을 입력하는 teacher forcing**을 사용합니다.

예를 들어 3단계에서는 정답 문장의 두 번째 토큰 `이`를 입력하고, 세 번째 토큰 `영화를`에 모델이 부여한 확률로 손실을 계산합니다. 손실은 Decoder뿐 아니라 초기 상태를 만든 Encoder의 가중치에도 영향을 줍니다.

정답 문장을 미리 알아도 LSTM은 현재 상태를 계산하려면 이전 상태가 필요합니다. 따라서 시간축의 순환 계산은 여전히 순서대로 수행합니다.

### 5-5. 남은 어려움: 마지막 요약에만 의존한다

이 구성에서는 입력 문장의 정보가 고정 크기의 마지막 상태 쌍을 통해 전달됩니다. 문장이 길어져도 전달하는 벡터 크기는 같으므로 번역에 필요한 세부 정보를 충분히 담기 어려울 수 있습니다. 이것이 **고정 벡터 병목**입니다.

다음의 Attention은 Decoder가 입력의 각 위치를 다시 참고하도록 바꿉니다.

## 6. Attention: 지금 필요한 입력 정보를 가중합하기

### 6-1. 마지막 상태뿐 아니라 모든 위치의 상태를 보관한다

Encoder가 각 토큰을 읽으며 만든 hidden state들을 보관합니다. 각 상태에는 해당 위치까지의 문맥 정보가 담깁니다. 여기서는 앞 절과 같은 단방향 Encoder를 가정합니다.

```text
입력:          I       love       this       movie
Encoder 상태: h₁        h₂         h₃          h₄
               └─────────┴──────────┴───────────┘
                    Decoder가 매 단계 참고
```

**Attention**은 여러 위치의 표현을 참고 비율에 따라 가중합하는 계산입니다. 아래는 LSTM Seq2Seq에 **Bahdanau 방식의 additive attention**을 붙인 예시입니다.

이 예시에서는 앞 절처럼 Encoder의 마지막 상태 쌍으로 Decoder를 초기화합니다. 여기에 매 출력 단계마다 모든 Encoder hidden state를 참고하는 경로를 추가합니다. Attention이 Decoder의 초기 상태나 LSTM의 내부 기억을 대체하는 것은 아닙니다.

### 6-2. 계산은 네 단계다

**첫째, 관련도 점수를 계산합니다.** Decoder의 이전 hidden state와 Encoder의 각 위치별 hidden state를 점수 신경망에 넣습니다. 출력 토큰을 만들기 위해 각 입력 위치를 얼마나 참고할지 점수를 구하는 것입니다.

**둘째, softmax로 참고 비율을 만듭니다.** 이 비율을 **attention weight**라고 합니다. 한 출력 시점에서 입력 위치들에 대한 비율의 합은 1입니다.

**셋째, Encoder 상태를 가중합합니다.** 각 상태에 참고 비율을 곱하고 더한 결과를 **context vector(문맥 벡터)**라고 합니다.

**넷째, Decoder가 그 결과를 사용합니다.** 예를 들어 이전 출력 토큰의 임베딩과 context vector를 이어 붙여 LSTM 입력으로 줄 수 있습니다. 새 hidden state를 구한 뒤 어휘 출력층으로 다음 토큰을 예측합니다.

```text
Decoder의 이전 hidden state와 Encoder의 각 hidden state를 함께 사용
    → 위치별 점수
    → softmax
    → attention weight
    → Encoder 상태의 가중합(context vector)
    → Decoder의 새 상태 계산
    → 다음 출력 토큰의 확률
```

### 6-3. 숫자로 보면 어떤 뜻인가?

어떤 출력 단계에서 다음 비율이 계산됐다고 가정하겠습니다.

| 입력 위치 | I | love | this | movie |
| --- | ---: | ---: | ---: | ---: |
| 참고 비율 | 0.05 | 0.80 | 0.05 | 0.10 |

```text
context = 0.05 × h₁ + 0.80 × h₂ + 0.05 × h₃ + 0.10 × h₄
```

이는 두 번째 위치의 표현을 더 크게 반영한다는 뜻입니다. 한 위치를 반드시 선택하는 것이 아니라 여러 위치의 벡터를 섞습니다. 다음 출력 단계에는 Decoder 상태가 달라지므로 참고 비율과 context도 달라질 수 있습니다.

여기서 **context vector와 LSTM의 cell state는 다른 값**입니다. Cell state는 LSTM 내부에서 유지하는 기억이고, context vector는 이번 단계에 Encoder 상태들을 가중합해서 얻은 입력 정보입니다.

### 6-4. 점수는 어떻게 계산하고 학습하는가?

Bahdanau 방식의 계산을 간단히 쓰면 다음과 같습니다.

```text
중간 벡터 = tanh(Ws × Decoder 이전 hidden state
                + Wh × Encoder의 j번째 hidden state
                + 편향)
j번째 위치의 점수 = 학습 벡터 v와 중간 벡터의 내적
```

**내적**은 같은 위치의 성분끼리 곱한 뒤 전부 더해 숫자 하나를 구하는 연산입니다. 두 상태를 변환한 결과를 더해서 점수를 만들기 때문에 additive attention이라고 부릅니다.

Ws, Wh, 편향, v는 학습 파라미터입니다. 반면 참고 비율 `0.80`은 이 파라미터와 현재 입력으로 계산한 결과입니다. 사람이 ‘love를 80% 보라’고 정해 주지 않습니다. 번역 정답에 대한 손실을 역전파하면서 점수 계산 파라미터도 함께 학습합니다.

| 비교 | LSTM 게이트 | 여기서의 Attention |
| --- | --- | --- |
| 조절 대상 | 기억 벡터의 각 성분 | Encoder의 각 입력 위치 |
| 비율 계산 | sigmoid | 위치별 점수에 softmax |
| 합이 1이어야 하는가? | 아니요 | 한 출력 시점의 위치별 비율 합은 1 |
| 학습 대상 | 게이트 값을 만드는 가중치·편향 | 관련도 점수를 만드는 파라미터 |

Bahdanau 원 논문은 GRU라는 다른 순환 셀과 양방향 Encoder를 사용했습니다. 여기서는 개념을 이어 설명하려고 LSTM에 적용했습니다. Attention을 사용하려면 반드시 LSTM이어야 하는 것은 아닙니다.

### 6-5. 남은 어려움: 순환 계산은 그대로다

입력을 참고하는 방법은 좋아졌지만, LSTM 상태는 여전히 이전 상태가 있어야 계산할 수 있습니다. Attention을 붙였다고 순환 연결이 사라지지는 않습니다.

다음의 Transformer는 토큰 사이 정보 교환을 Attention으로 수행하면서 시간축 순환 연결을 없앱니다.

## 7. Transformer: Attention으로 토큰 사이 정보를 교환하기

### 7-1. RNN과 무엇이 달라지는가?

RNN은 이전 시점의 상태를 넘겨받아 현재 상태를 계산했습니다. Transformer는 각 층에서 여러 토큰의 표현을 함께 받아, Attention으로 다른 위치의 정보를 모읍니다.

```text
RNN:          앞 시점 상태 → 다음 시점 상태 → 그다음 시점 상태
Transformer:  같은 층의 입력 표현들 → 위치 간 Attention → 새 표현들
```

이 비교는 **입력으로 주어진 토큰들의 표현을 계산하는 방법**에 대한 것입니다. 새로운 문장을 생성하는 순서와는 구분해야 합니다. 생성은 뒤에서 따로 살펴봅니다.

### 7-2. 위치 정보를 함께 넣는다

시간축 순환 연결이 없으므로 토큰 순서를 표현하는 정보가 따로 필요합니다. 2017년 원형 Transformer는 토큰 임베딩에 **위치 인코딩(positional encoding)**을 더했습니다.

```text
첫 층 입력 = 토큰 임베딩 + 해당 위치의 인코딩
```

같은 토큰이라도 어느 위치에 놓였는지 구별할 수 있도록 하는 것입니다. 후속 모델에는 위치 정보를 반영하는 다른 방식도 있습니다.

### 7-3. Query, Key, Value

Transformer의 Attention은 토큰 표현에서 **Q(Query), K(Key), V(Value)**를 만듭니다.

| 벡터 | 계산에서 하는 일 |
| --- | --- |
| Q | 이번 위치에서 다른 위치의 점수를 구할 때 사용 |
| K | 각 Q와 비교해 참고 점수를 계산 |
| V | 참고 비율에 따라 실제로 가중합할 정보 |

```text
Q = 입력 표현 × WQ
K = 입력 표현 × WK
V = 입력 표현 × WV
```

WQ, WK, WV는 서로 다른 학습 가중치입니다. 가중치 행렬을 곱해 입력을 Q·K·V 표현으로 바꾸는 연산을 여기서는 **투영(projection)**이라고 부릅니다. 여기서는 토큰 표현을 행으로 놓았기 때문에 가중치를 오른쪽에 곱합니다. 앞의 RNN 표기는 벡터를 열로 놓아 왼쪽에 곱했습니다.

각 위치의 Q와 참고할 위치들의 K를 내적해서 점수를 만듭니다. Q와 K의 차원 수는 내적할 수 있도록 맞춥니다. 이어서 점수 크기를 조정하고 softmax를 적용한 뒤 V를 가중합합니다. 아래 softmax는 **Q 하나에 대해 참고할 K 위치들 사이에서** 비율을 구합니다.

```text
점수 = Q와 K의 내적 / √(Key의 차원 수)
참고 비율 = softmax(점수)
결과 = 참고 비율로 V들을 가중합
```

차원 수의 제곱근으로 나누는 것은 내적의 크기가 커져 softmax가 지나치게 일부 위치에 집중하는 것을 완화합니다. 이 계산을 **scaled dot-product attention**이라고 합니다. Bahdanau 방식과 가중합 목적은 같지만, 점수를 구하는 방법이 다릅니다.

Q·K·V와 참고 비율은 매 입력에서 계산합니다. 학습해서 저장하는 것은 이 값들을 만드는 가중치입니다.

### 7-4. Self-Attention과 Cross-Attention

**Self-Attention**은 Q와 K·V를 같은 시퀀스의 표현에서 만듭니다. 문장 안의 토큰들이 서로 참고하는 계산입니다.

**Cross-Attention**은 Q와 K·V를 서로 다른 시퀀스에서 만듭니다. 번역용 Transformer에서는 Decoder가 Q를 만들고, Encoder 최종 출력에서 K·V를 만듭니다. 출력 문장이 입력 문장을 참고하는 것입니다.

| 번역용 Transformer의 계산 | 참고하는 대상 |
| --- | --- |
| Encoder Self-Attention | 자기 위치를 포함한 입력 문장 전체 |
| Decoder Self-Attention | 출력 이력 안의 허용된 위치 |
| Decoder Cross-Attention | Encoder가 만든 입력 문장의 표현 |

Encoder–Decoder라는 역할은 Seq2Seq 때와 같습니다. 그 역할을 수행하는 내부 부품이 LSTM에서 Transformer 블록으로 바뀌었습니다.

### 7-5. 미래를 못 보게 하는 causal mask

다음 토큰 예측에서는 정답이 있는 미래 위치를 미리 보면 안 됩니다. 그래서 Decoder Self-Attention에 **causal mask(인과 마스크)**를 적용합니다.

```text
1번 위치 → 1번까지만 참고
2번 위치 → 1~2번만 참고
3번 위치 → 1~3번만 참고
```

구현에서는 softmax 전에 가릴 위치의 점수에 음의 무한대를 더해 그 위치의 참고 비율을 0으로 만듭니다. 길이를 맞추려고 덧붙인 채움 토큰인 **padding**도 mask로 제외할 수 있습니다.

Encoder는 번역할 입력 문장이 이미 전부 주어져 있으므로 일반적으로 입력 양쪽 문맥을 참고할 수 있습니다. Decoder의 Cross-Attention도 입력 문장 전체를 참고할 수 있습니다.

### 7-6. Attention 외에 필요한 부품

**Multi-Head Attention**은 서로 다른 Q·K·V 투영을 사용하는 여러 Attention 계산을 병렬로 수행합니다. 한 계산 단위를 head라고 합니다. 각 결과를 이어 붙이고 출력 가중치로 변환해 합칩니다. 서로 다른 관계를 표현할 수 있는 여러 계산 경로를 제공하는 것입니다.

**FFN(Feed-Forward Network)**은 Attention이 모은 토큰 표현을 위치별로 변환하는 신경망입니다. 원형 Transformer에서는 두 선형 변환 사이에 비선형 함수 ReLU를 적용합니다. 같은 층에서는 모든 위치에 같은 FFN 가중치를 적용합니다. Attention은 위치 사이 정보를 섞고, FFN은 각 위치의 표현을 변환합니다.

**잔차 연결(residual connection)**은 하위 층의 입력을 그 계산 결과에 더합니다. 정보와 기울기가 여러 층을 지나 전달되는 데 도움이 됩니다.

**LayerNorm**은 토큰 표현의 성분들을 정규화하고 학습 가능한 배율과 편향을 적용하는 연산입니다. 여러 층을 쌓은 모델의 학습을 안정화하는 데 사용합니다.

2017년 원형 Transformer의 큰 구성은 다음과 같습니다. Attention과 FFN 하위 층에는 각각 잔차 연결과 LayerNorm이 붙습니다.

```text
Encoder 블록: Self-Attention → FFN
Decoder 블록: Causal Self-Attention → Cross-Attention → FFN
```

블록을 여러 층 쌓으면 앞 블록의 출력이 다음 블록의 입력이 됩니다. Decoder의 각 Cross-Attention은 Encoder 최종 출력을 참고합니다.

마지막 Decoder 블록의 각 토큰 표현은 어휘 출력층과 softmax로 전달됩니다. LSTM 때처럼 후보 토큰별 확률을 구하는 것이며, 그 앞에서 표현을 계산하는 방식이 바뀐 것입니다.

### 7-7. 학습은 여러 위치를 병렬 계산할 수 있다

학습에서는 정답 문장을 알고 있으므로 한 칸 밀어 Decoder 입력으로 줍니다.

| 위치 | Decoder 입력 | 예측할 정답 |
| --- | --- | --- |
| 1 | `<BOS>` | 나는 |
| 2 | 나는 | 이 |
| 3 | 이 | 영화를 |
| 4 | 영화를 | 좋아한다 |
| 5 | 좋아한다 | `<EOS>` |

3번 위치는 `이`까지 보고 다음 토큰을 예측하며, 정답은 `영화를`입니다. Causal mask가 4번 이후 입력을 가려 정답을 미리 보지 못하게 합니다.

LSTM과 달리 시간축 순환 연결이 없으므로, **이미 주어진 정답 입력의 여러 위치를 같은 층에서 병렬 계산**할 수 있습니다. 다만 층 사이에는 의존성이 있으므로 다음 층은 앞 층의 결과가 필요합니다.

### 7-8. 생성은 여전히 한 토큰씩 진행한다

추론에서 번역문은 아직 주어지지 않았습니다. 직전에 선택한 토큰을 다음 입력에 붙여야 하므로 순서대로 생성합니다. 이를 **자기회귀(autoregressive) 생성**이라고 합니다.

```text
<BOS>로 시작
    → '나는' 선택
    → 토큰 '나는'을 입력 이력에 붙이고 '이' 선택
    → '이'를 붙이고 '영화를' 선택
    → 이후 같은 방식으로 반복
    → <EOS>를 선택하면 종료
```

**KV cache**는 이전 토큰의 Key·Value를 저장해 재사용하는 방법입니다. 중복 계산은 줄이지만, 다음 입력 토큰을 정해야 그다음 토큰을 생성할 수 있다는 순서를 없애지는 않습니다.

또한 모든 위치 쌍을 비교하는 Self-Attention은 길이 n에 대해 n²개의 관련도 점수를 다룹니다. 순환 연결을 없앴어도 긴 입력의 계산 비용은 남습니다.

## 8. BERT와 GPT: 어떤 문맥으로 무엇을 예측할까?

지금까지는 번역을 위해 Encoder와 Decoder를 함께 사용했습니다. 이번에는 한쪽 계열의 블록을 사용해 많은 텍스트로 언어 패턴을 익히는 **사전학습(pre-training)**을 살펴봅니다.

사전학습한 모델을 특정 작업의 데이터로 추가 학습하는 것을 **미세조정(fine-tuning)**이라고 합니다.

다음 토큰 예측과 가린 토큰 복원에서는 원문 자체에서 정답을 만들 수 있습니다. 이처럼 데이터에서 학습할 정답을 구성하는 방식을 **자기지도학습(self-supervised learning)**이라고 합니다. 번역 학습에 입력 문장과 번역문 쌍을 사용하는 것과 데이터 구성 방식이 다릅니다.

### 8-1. BERT: 양쪽 문맥으로 토큰 복원하기

**BERT**는 Transformer Encoder 블록을 쌓은 모델입니다. 대표적인 학습 과제는 입력 일부를 가리고 원래 토큰을 맞히는 **Masked Language Modeling(MLM)**입니다.

```text
입력: I [MASK] this movie
복원할 정답: love
```

가린 위치는 왼쪽의 `I`와 오른쪽의 `this movie`를 모두 참고할 수 있습니다. 마지막 Encoder 표현에 예측용 출력층을 붙여 원래 토큰의 확률을 계산합니다.

`[MASK]`는 원래 토큰 대신 입력하는 특수 토큰입니다. Transformer Decoder의 causal mask처럼 특정 위치에 대한 Attention을 금지하는 장치가 아닙니다. BERT는 가린 위치의 표현을 계산할 때도 주변 토큰을 참고합니다.

원형 BERT에서는 복원 대상으로 고른 토큰을 모두 `[MASK]`로 바꾸지는 않습니다. 일부는 임의 토큰으로 바꾸거나 그대로 두고 원래 토큰을 예측합니다.

원형 BERT는 두 입력 구간이 원문에서 이어지는지 맞히는 **Next Sentence Prediction(NSP)**도 사전학습했습니다. 입력에는 토큰·위치 임베딩과 함께 두 구간을 구분하는 **segment 임베딩**을 사용했습니다.

사전학습 뒤에는 작업에 맞는 출력층을 붙여 문장 분류나 지문에서 답의 범위를 찾는 질의응답 등에 사용할 수 있습니다. 기본 BERT에는 다음 토큰을 계속 이어 쓰기 위한 자기회귀 Decoder가 없습니다.

### 8-2. GPT: 앞의 문맥으로 다음 토큰 예측하기

**GPT**는 Causal Self-Attention을 사용하는 Decoder 계열 블록을 쌓습니다. 번역용 Transformer Decoder에 있던 Encoder–Decoder Cross-Attention은 없습니다.

```text
입력: I love this
다음 정답 토큰: movie
```

모델은 현재까지 입력된 토큰만 보고 그다음 토큰을 예측하도록 사전학습합니다. 문장 안의 여러 위치에서 다음 토큰 손실을 계산해 학습할 수 있습니다.

생성의 출발점으로 제공한 텍스트를 **프롬프트(prompt)**라고 합니다. 생성할 때는 프롬프트와 지금까지 생성한 토큰을 하나의 입력 이력으로 사용합니다.

```text
프롬프트: I love this
    → movie 생성
입력 이력: I love this movie
    → 다음 토큰 생성
```

생성할 때는 현재 입력의 마지막 토큰 표현을 어휘 출력층에 넣어 다음 토큰 확률을 구합니다. 학습할 때는 앞서 설명한 causal mask를 적용해 여러 위치에서 다음 토큰 예측을 병렬로 계산합니다. 이 노트는 GPT 계열의 기본적인 텍스트 언어 모델 원리를 다루며, 대화용 모델을 만들기 위한 추가 학습 과정은 다루지 않습니다.

### 8-3. 두 모델의 차이 정리

| 비교 항목 | BERT | GPT |
| --- | --- | --- |
| 기본 블록 | Transformer Encoder | Causal Transformer Decoder 계열 |
| 참고 문맥 | 입력의 왼쪽과 오른쪽 | 현재 위치까지의 토큰 |
| 대표 사전학습 과제 | 선택한 입력 토큰 복원 | 다음 토큰 예측 |
| 예측의 위치 | 입력 문장 안 | 현재 입력 이력 다음 |
| 대표 활용 | 문장·토큰 표현을 이용한 분석 | 입력에 토큰을 이어 붙이는 생성 |

‘BERT는 이해용, GPT는 생성용’은 대표 활용을 줄여 말한 표현입니다. GPT도 분류에 사용할 수 있으므로, 능력을 둘로 나누기보다 문맥 방향과 학습 목표를 구분하는 것이 정확합니다.

## 9. 전체 흐름 복습

```text
토큰과 임베딩: 텍스트를 숫자 벡터로 바꾼다.
        ↓
RNN: 이전 상태를 다음 시점의 계산에 전달한다.
        ↓
LSTM: cell state와 게이트로 기억의 갱신을 조절한다.
        ↓
Seq2Seq: 입력을 읽는 Encoder와 출력을 만드는 Decoder를 연결한다.
        ↓
Attention: 출력 시점마다 입력 위치들의 표현을 다시 가중합한다.
        ↓
Transformer: Attention과 FFN으로 표현을 계산하며 시간축 순환을 없앤다.
        ↓
BERT / GPT: 양방향 토큰 복원과 인과적 다음 토큰 예측으로 나뉘어 살펴본다.
```

다음 구분을 설명할 수 있으면 핵심 흐름을 이해한 것입니다.

| 혼동하기 쉬운 것 | 구분 |
| --- | --- |
| RNN과 LSTM | LSTM은 RNN에 사용하는 셀의 한 종류 |
| LSTM과 Seq2Seq | 셀의 계산 방식과 Encoder–Decoder 구성 방식 |
| Cell state와 context vector | LSTM 내부 기억과 Attention이 가중합한 입력 정보 |
| Output gate와 어휘 출력층 | Hidden state 반영 비율 계산과 후보 토큰 점수 계산 |
| 학습 가중치와 attention weight | 저장하며 갱신하는 파라미터와 현재 입력에서 구한 참고 비율 |
| 역전파와 생성 | 손실에서 기울기를 구하는 학습 계산과 토큰을 선택해 이어 쓰는 과정 |
| 병렬 학습과 순차 생성 | 주어진 위치들의 표현 계산과 아직 없는 다음 토큰의 선택 |
